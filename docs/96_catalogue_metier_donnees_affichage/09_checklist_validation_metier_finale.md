# Checklist validation métier finale

| Axe | Question | Oui/Non | Commentaire |
|---|---|---|---|
| Paramètres | Les paramètres affichés sont-ils ceux attendus par l'ABH ? | | |
| Paramètres | La distinction `MO` / `Mo` est-elle jugée claire ? | | |
| Paramètres | `FM`, `F_M_MES` et `MD` sont-ils correctement classés ? | | |
| Supports | Les supports `RIVIERE`, `NAPPE`, `BARRAGE`, `SEBOU` sont-ils compréhensibles ? | | |
| Campagnes | Les campagnes sont-elles séparées de la restitution courante ? | | |
| Périodes | La séparation récent / moyen terme / historique / archive est-elle valide ? | | |
| Vues | Les vues SQL spécialisées reflètent-elles bien la vision métier cible ? | | |
| APIs | Les endpoints P0 exposés répondent-ils au besoin de validation immédiate ? | | |
| Affichage | Les modes carte / tableau / graphique sont-ils utiles et bien hiérarchisés ? | | |
| Affichage | Les états `à venir` sont-ils suffisants pour les modules non branchés ? | | |
| Qualité | Les informations QA doivent-elles être plus visibles ? | | |
| Historique | L'historique reste-t-il accessible sans surcharger les écrans décisionnels ? | | |
| Temps réel | La future télémesure doit-elle être isolée ou fusionnée visuellement ? | | |
| Consultation | Les paramètres `CONSULTATION_ONLY` sont-ils au bon niveau de visibilité ? | | |
| Exclusions | Les paramètres hors restitution doivent-ils rester invisibles en public ? | | |

## Critères de clôture atelier

- validation des familles P0 ;
- validation des campagnes ;
- validation des priorités ;
- validation des exclusions ;
- validation de la stratégie d'ingestion future.
